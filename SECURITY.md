# Security

This is experimental software. Only private-dry-run mode is implemented; no version has a formal support or security guarantee.

Do not put sensitive evidence in public issues. Use GitHub's private vulnerability reporting if enabled by the repository owner. If unavailable, request a private reporting channel without disclosing exploit details or private data.

The maintainer should enable private vulnerability reporting before public release. Keep credentials in the host credential store. Run untrusted repositories in an appropriately isolated environment. Public previews must contain only cleared content; development servers can expose source and diagnostics. Text-pattern checks and evidence attestations are not comprehensive security controls.
