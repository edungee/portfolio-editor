# Collecting the pilot
Read each registered source using its locator and the host's matching capability. Local Git: read log/diffs in the configured path; never pull or change source repositories. Notion: fetch the specified page, retain its content and revision, inspect truncation/unknown blocks. App tasks: read the configured task, page backwards until its previous checkpoint or declared bounded scope is covered; filter to user/assistant text before serializing. Never retain image base64 or tool outputs. Truncated messages, missing attachments material to a claim and incomplete pagination mean partial coverage.

A checkpoint is source-specific. Use an overlap on incremental reads and the existing claim IDs to avoid repetition. No-change complete reads can advance a checkpoint; failed or partial reads cannot. Start with all registered sources on the first run. A fresh run must fetch fresh evidence, not replay the initial validation batch. The scheduler invokes the agent and skill; the script processes the resulting batch.

Read current repository content each time. Refreshing from GitHub is a separate read operation; compare against default-branch content before any delivery mode. For this pilot a local-only baseline must be disclosed. Preserve prior run inputs as private evidence. Remove a stale lock only after verifying its recorded PID is not running and reviewing any incomplete run.
